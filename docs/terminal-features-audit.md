# Проверка встроенных возможностей Rio на macOS

Дата: 2026-10-27. Проверен код `5b6a720a2e70d5668eb904df0725e91581adf66e`, release arm64 (Rio 0.5.28 с нашими workspaces). Рабочая конфигурация пользователя и установленное приложение не изменялись. UI-проверки выполнялись в отдельном `/tmp/RioFeatureAudit.app` с `RIO_CONFIG_HOME=/tmp/rio-feature-audit/config`.

Это проверка шести ранее перечисленных функций, а не новой реализации. Наличие названия действия в enum само по себе не считалось успешной проверкой.

## Что действительно требует настройки

### Поиск и Vi

В коде macOS заданы Cmd+F (поиск вперёд), Cmd+B (назад), Alt+Shift+Space (Vi). В Vi доступны стрелки/hjkl, v для выделения и y для копирования. При русской раскладке буквенные команды и метки могут не совпадать; в проверке использовалась латинская.

Источники: [bindings](../frontends/rioterm/src/bindings/mod.rs), [screen](../frontends/rioterm/src/screen/mod.rs), [Vi core](../rio-vt/src/crosswords/vi_mode.rs).

### Hints

Стандартная конфигурация содержит правило URL/путей с Open, клавишами Ctrl+Shift+O и обработкой OSC 8 ссылок. Пользовательские regex-правила могут выполнять Copy, Paste, Select, MoveViModeCursor, Open или заданную программу с argv. Это уже существующая возможность; новую систему Quick Select писать с нуля не нужно.

В тестовом конфиге правило Copy привязано к F3, Open локального файла — к F6. Это примеры проверки, не изменения пользовательских сочетаний.

Источники: [схема hints](../rio-backend/src/config/hints.rs), [поиск и выбор hints](../frontends/rioterm/src/hints.rs).

### Промпты: важное уточнение предыдущего обзора

`ScrollToPrevPrompt` и `ScrollToNextPrompt` реализованы и работают. Но встроенный `rio-integration.zsh` передаёт каталог через OSC 7, **не OSC 133**. Нельзя обещать, что одной привязки клавиш достаточно для обычного zsh. Тема или отдельная shell-интеграция должны помечать промпты.

Минимальный проверенный zsh-hook:

```zsh
autoload -Uz add-zsh-hook
_rio_mark_prompt() { builtin printf '\e]133;A\a'; }
add-zsh-hook precmd _rio_mark_prompt
```

Он проверен только в изолированном shell; пользовательский `.zshrc` не редактировался. Если тема уже отправляет OSC 133 A, дублировать hook не нужно. Этот hook обеспечивает навигацию, но не добавляет историю команд, длительность, exit code или автоматические уведомления.

Источники: [встроенная zsh-интеграция](../frontends/rioterm/src/shell_integration/rio-integration.zsh), [разбор OSC 133](../rio-vt/src/performer/osc.rs), [scroll_to_prompt](../rio-vt/src/crosswords/mod.rs).

### Quake: подтверждённая часть и предел проверки

Настройка — обычное действие `ToggleQuake` в `[bindings].keys`; отдельного штатного сочетания по умолчанию нет. Размер задаётся `window.quake-width-percentage` и `window.quake-height-percentage`.

После отдельного запуска с INFO-логом приложение сообщило `registered global hotkey: F12`. Таким образом, зарегистрировать сочетание удалось. Но при отправке синтетического F12 из TextEdit окно не появилось — повторено с удержанием 200 мс. Это **не успешная проверка глобального вызова** и само по себе ещё не доказательство поломки физического сочетания: синтетические события автоматизации могут доставляться иначе, чем физическая клавиатура. Нужна отдельная проверка реальным нажатием вне Rio. Утверждать, что этот сценарий полностью работает, пока нельзя.

Источники: [регистрация global hotkeys](../frontends/rioterm/src/global_hotkey.rs), [создание/показ/скрытие Quake](../frontends/rioterm/src/application.rs), [создание окна](../frontends/rioterm/src/router/mod.rs).

### Bell

```toml
[bell]
tab-indicator = true
```

Индикатор по умолчанию включён. Для активной вкладки сфокусированного окна отметка не ставится. Для фоновой ставится один раз, при фокусировке очищается. Сигнал можно проверить командой `printf '\a'`; чтобы увидеть именно фоновый индикатор, запланировать сигнал через `sleep 10` и переключиться до его прихода.

Источники: [конфиг](../rio-backend/src/config/bell.rs), [обработка события](../frontends/rioterm/src/application.rs), [состояние вкладки](../frontends/rioterm/src/context/mod.rs), [рисование точки](../frontends/rioterm/src/renderer/island.rs).

## Воспроизведение

Из корня репозитория:

```sh
mkdir -p /tmp/rio-feature-audit/config
cp extra/feature-audit/config.toml /tmp/rio-feature-audit/config/config.toml
cp extra/feature-audit/fixture.sh extra/feature-audit/prompts.sh extra/feature-audit/mark-prompts.zsh extra/feature-audit/open-target.txt /tmp/rio-feature-audit/
RIO_CONFIG_HOME=/tmp/rio-feature-audit/config cargo run -p rioterm --release --locked
```

Конфиг предназначен для отдельного тестового процесса. Не копируйте его целиком поверх рабочего конфига: он задаёт чистый zsh, тестовые пути и глобальный F12.

Внутри тестового Rio:

```sh
PS1='AUDIT> '; /bin/sh /tmp/rio-feature-audit/fixture.sh
# F1 → запрос AUDIT_FIND_NEEDLE_314159 → Enter; Escape отменяет поиск.
# F2 → Vi; стрелки и v; F8 → Copy; F2 → выйти.
# F3 → j копирует hint. F6 → j открывает тестовый файл.
/bin/sh /tmp/rio-feature-audit/prompts.sh
# F4 дважды → F5: PROMPT_3 → PROMPT_2 → PROMPT_3.
source /tmp/rio-feature-audit/mark-prompts.zsh
# Выводите несколько длинных блоков; F4/F5 теперь находят настоящие zsh-промпты.
```

F9 создаёт вкладку; F10/F11 переключают. F12 показывает/скрывает Quake. Bell: `(sleep 10; printf '\a') &`, затем F9/F10 до прихода сигнала.

## Автоматические проверки и уборка

`cargo test -p rioterm -p rio-backend -p rio-vt --locked` — **1024 теста прошли, 0 ошибок** (230 frontend, 230 backend/config, 564 VT, плюс doc-test группы без тестов). Среди них проверки hints, semantic prompt navigation, bell/focus и парсинга глобальных сочетаний. Эти тесты дополняют, а не заменяют UI-проверки выше.

Тестовый Rio завершён штатным Quit, его глобальный F12 освобождён. Тестовый файл TextEdit закрыт, исходная раскладка клавиатуры возвращена. Пользовательский Rio, его процессы и конфиг не менялись. Изменений в исполняемый код по результатам этой проверки нет.
